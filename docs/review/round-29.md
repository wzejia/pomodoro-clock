# Round 29 评审（v6.1 第三轮）

## 原始输出（独立评审子智能体，仅给八态截图 + Apple HIG 标准）

**结论：本轮有 P1（2 条，同一根因，明暗两态同坐标复现，经 3x/4x 裁剪放大 + 像素几何实测确认）。**

- P1-1 drawer 两态 ——「循环」分组卡把「自动开始下一阶段」开关拦腰裁断（toggle 轨道仅剩 14px 高、底部平切）
- P1-2 drawer 两态 ——「时长」分组卡第三行（长休息）只剩约 8px 残条，步进器上半截残影贴卡下缘
- P3-1 ctx 菜单宽度相对单项内容过宽（矮胖）
- P3-2 mini-dark 顶部镜面高光带亮度偏高

## 分诊

- P1-1/P1-2 **成立，真 bug**：v6.1 加材质行后抽屉内容自然高（~440px）超可用（368px）；overflow:hidden 的 flex 子项 min-height:auto 计算为 0 → 分组卡被 flex-shrink 压矮并裁行尾。其实 v6 时代已隐性裁切（吃的是行 padding 余量，控件未受伤），材质行把它推过临界点。修：行垂直 padding 12→9（省 42px）+ 抽屉 padding 20→14、gap 10→6、头 margin 10→4（省 22px）→ 实测三卡末行余量归正、toggle 22px 完整、行高 43/44px 全恢复。裁切实证裁剪图 tmp/r29-toggle-zone.png
- P3-1/P3-2 → BLOCKED 留裁（菜单宽度涉既有设计；深色高光强度偏好）
